The problem

Your database is a PII inventory.

HTTPS protects transit. A DB dump, stolen backup, read replica or SQL injection still exposes customer emails and user data at rest — unless the fields themselves are encrypted.

Default Laravel

Emails live in plaintext

The users table, password reset tokens, backups and exports can all contain readable email addresses.

Hashing alone

Login and uniqueness break

One-way hashes protect values, but you still need case-insensitive login, reset lookup and duplicate registration.

DIY crypto

Rotation and migration are risky

Rolling your own key handling makes existing data, key rotation and rollback easy to get wrong.

How it works

Default deny: only fields listed in the config are encrypted. No core patches and no forced framework changes.

▦

One config map

List up to 20 fields per model with optional index and normalization settings.

🔐

AES-256-GCM

Randomized authenticated encryption with a key id in every payload for rotation.

🔎

Blind index

HMAC-SHA256 of the normalized value and field name; exact lookup without plaintext in the index.

👤

Email login

The custom user provider maps email credentials to the encrypted email index.

🔁

Password reset

The encrypted-database broker driver stores a blind index in the reset-token table.

Install

Requires PHP 8.1+, Laravel 10/11/12 and OpenSSL. Back up the database before encrypting existing rows.

01

Add the GitHub VCS package and publish config/migration.

02

Set the key ring, token secret and model field map.

03

Backfill, switch auth/password drivers and test login.

composer config repositories.encrypted-fields vcs https://github.com/thiennhant95/laravel-encrypted-fields
composer require thiennhant95/laravel-encrypted-fields:^0.1

php artisan vendor:publish --tag=encrypted-fields-config
php artisan vendor:publish --tag=encrypted-fields-migrations

FAQ

Questions buyers ask

Does it encrypt the email column too?

Yes. The email itself is AES-256-GCM ciphertext; a separate email_bidx column stores a normalized HMAC for exact lookup and uniqueness.

Can users still log in and reset passwords?

Yes. The custom user provider maps login credentials to email_bidx, and the encrypted password broker keeps reset tokens free of plaintext email.

Can I search email partially?

No. Blind indexes support exact equality only. Partial LIKE search would require a separate token index and is outside this package.

How do I validate unique emails?

Use EncryptedUnique(User::class, 'email') instead of Laravel's default unique:users,email, because the stored email is ciphertext.

What happens if I lose the key?

Encrypted values are unrecoverable without the key. Keep backups of the key ring outside the database and rehearse rotation before changing keys.

Can I encrypt 20 fields?

Yes. Add any number of fields to the model map. Fields with an index get blind-index lookup; fields without one are encrypted only.

Is it free?

Yes. GPL-2.0-or-later, source and releases on GitHub. No paid tier, telemetry or key escrow.
